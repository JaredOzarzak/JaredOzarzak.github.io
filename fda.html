FDA Device Reports: What Gets Reported, and Can You Trust It?

Why I did this

Can you actually trust public data?

The FDA puts every medical device problem report online for free. Sounds great, but the raw data is messy: nested JSON, bad dates, the same device spelled five different ways. I wanted to do what an analyst does on day one: pull real data, clean it, put it in a database, and make sure it's right before answering anything.

The data

What I pulled

  • 10,000 reports from 2025, pulled from the openFDA API in 10 calls of 1,000 each
  • 11 fields kept: things like date received, event type, device name, manufacturer, and device class
  • Heads up: these are the first 10,000 reports the API gave back, not a random sample. And a report doesn't prove a device caused harm
How I did it

Step by step

1. Pull it (Python)

The API only gives 1,000 records at a time, so I wrote a loop that grabs 10 pages, retries if a call fails, and waits a second between calls so I don't get blocked.

2. Look before cleaning

Before changing anything, I checked every column: what's missing, what's duplicated, what looks weird. You can't fix what you haven't looked at.

3. Clean it (pandas)

Removed duplicates, fixed dates (bad ones became blank instead of breaking everything), and made text match so "Infusion Pump" and "infusion pump " count as the same device.

I also figured out reporting lag: how many days between the event and the FDA getting the report. Anything under 0 days or over 10 years got flagged, because that's not possible. That caught 23 bad dates.

4. Ask questions (SQL)

I loaded the clean data into SQLite and answered 5 questions: event type breakdown, top 10 device types, monthly trend, top manufacturers, and reports by medical specialty. Here's the monthly trend one:

-- Reports per month + % change from last month
WITH m AS (
  SELECT substr(date_received, 1, 7) AS month, COUNT(*) AS reports
  FROM events GROUP BY month)
SELECT month, reports,
       ROUND(100.0 * (reports - LAG(reports) OVER (ORDER BY month))
             / LAG(reports) OVER (ORDER BY month), 1) AS mom_pct
FROM m ORDER BY month;

In plain English: count reports each month, then compare each month to the one before it.

What I found

The results

  • 61.5% of reports were device malfunctions
  • The most-reported device type was dental implants, with 1,873 reports
  • 23 reports had impossible dates. If you didn't catch those, any "average time to report" number would be wrong

Why it matters

  • A device company could track its own products' reports month to month and catch problems early
  • Anyone reporting time-based numbers needs to check dates first, or the average is off
